# Community Guidelines

## Tone and Communication

### Always
- Be welcoming to newcomers
- Assume good intent
- Thank people for contributions
- Explain decisions clearly
- Be patient with questions

### Never
- Be dismissive or condescending
- Ignore contributions or questions
- Use jargon without explanation
- Make people feel unwelcome

## Response Guidelines

### Issue Response Time
| Priority | Target |
|----------|--------|
| Security | < 24 hours |
| Critical bug | < 48 hours |
| Other issues | < 1 week |

### PR Review Time
- First response: < 3 days
- Follow-up reviews: < 2 days

## First-Time Contributors

- Use `good-first-issue` label for accessible tasks
- Provide extra guidance and context
- Be encouraging, even if changes needed
- Celebrate their first merged PR

## Code of Conduct

Reference: `CODE_OF_CONDUCT.md`

Key points:
- Respectful communication
- Inclusive environment
- No harassment or discrimination
- Constructive feedback only

## Language Policy

- **Discussions**: Reply in the language of the question
- **Code/Docs/PRs/Issues**: English
- **Exceptions**: Korean OK in ko/ prefixed docs

## Declining Contributions

When saying no:
1. Thank them for the effort
2. Explain the reason clearly
3. Suggest alternatives if possible
4. Be kind but firm

Example:
```
Thanks for this PR! We appreciate the effort.

Unfortunately, we can't merge this because [reason].

If you'd like to contribute, here are some alternatives:
- [suggestion 1]
- [suggestion 2]

Thanks for understanding!
```

## Handling Conflicts

1. Stay calm and professional
2. Move heated discussions to private channels
3. Involve other maintainers if needed
4. Document decisions for transparency

## Recognition

- Credit contributors in release notes
- Highlight significant contributions
- Consider adding active contributors to CONTRIBUTORS.md
