Schema defines the structure of interaction data. Before storing data, define how edges are structured, what properties they have, and how they can be queried.

See [Core Concepts](/design/concepts/) for background.

## Schema Hierarchy

<Aside type="note">
  Actionbase was open-sourced during the v3 transition. Schema API is still moving to v3, but examples use working v2, so you can follow along without issues. See the last section for v2/v3 mapping.
</Aside>

```
Database
├── Table (edge schema)
│   ├── Schema (source, target, properties)
│   └── Indexes (for querying)
└── Alias (alternative name for Table)
```

- **Database** groups related Tables and Aliases
- **Table** defines the schema for edges
- **Alias** provides an alternative name for a Table

## Database

A namespace that contains tables and aliases.

| Property | Description                             |
| -------- | --------------------------------------- |
| database | Database identifier (e.g., `myservice`) |
| comment  | Description                             |
| active   | Whether active                          |

Example: an e-commerce database might contain tables for `likes`, `recent_views`, and `purchases`.

## Table

Defines the schema for edges—source, target, properties, and indexes.

| Property | Description                                           |
| -------- | ----------------------------------------------------- |
| database | Parent database                                       |
| table    | Table identifier                                      |
| comment  | Description                                           |
| schema   | Edge structure (source, target, properties, direction, indexes) |
| mode     | Mutation mode (SYNC, ASYNC)                           |
| storage  | Storage URI (e.g., `datastore://<namespace>/<table>`) |
| active   | Whether active                                        |

### Schema Definition

- **source**: source type (STRING, LONG) — who
- **target**: target type (STRING, LONG) — what
- **properties**: each with name, type, nullable
- **direction**: direction type (IN, OUT, BOTH)
- **indexes**: for querying

**Example: Recent Views**

```
source: user_id (LONG)
target: product_id (LONG)
properties:
  - created_at (LONG)
direction: BOTH
```

**Example: Reactions**

```
source: user_id (LONG)
target: product_id (LONG)
properties:
  - created_at (LONG)
  - reaction_type (STRING)
direction: BOTH
```

### Index Definition

Indexes enable efficient querying. Each index has a name and a list of fields with sort order.

```
indexes:
  - index: by_created_at
    fields: [created_at DESC]
  - index: by_type_and_time
    fields: [reaction_type ASC, created_at DESC]
```

Indexes are pre-computed at write time. See [Query](/design/query/).

## Alias

An alternative name for a table.

| Property | Description              |
| -------- | ------------------------ |
| database | Parent database          |
| alias    | Alias identifier         |
| table    | The table it points to   |
| comment  | Description              |
| active   | Whether active           |

Useful for gradual migrations or domain-specific naming.

## Naming Conventions

| Type     | Format            | Example             |
| -------- | ----------------- | ------------------- |
| Database | Simple identifier | `myservice`         |
| Table    | `database.table`  | `myservice.likes`   |
| Alias    | `database.alias`  | `myservice.friends` |

## Schema Versions

v2 and v3 map almost 1:1.

| v2 (Current) | v3 (Future)  |
| ------------ | ------------ |
| service      | database     |
| label        | table        |
| src          | source       |
| tgt          | target       |
| ts           | version      |
| fields       | properties   |
| dirType      | direction    |
| indices      | indexes      |
| desc         | comment      |
