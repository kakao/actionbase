This guide walks you through building a simple social media application using Actionbase. You will learn how to model and serve activity data for core features such as **follows**, **likes**, and **feeds**.

## What You Will Build

By the end of this guide, you will have implemented:

- **Follows** - Users can follow other users
- **Likes** - Users can like posts
- **Feed** - Display posts from followed users with real-time like counts

These features demonstrate the core pattern behind most social applications.

### Build Follows

The guide walks you through building a follow feature: creating a table, adding a relationship, and querying the data.

#### Create the Follows Table

The guide creates a `user_follows` table to track who follows whom:

```bash
create table \
--database social \
--storage datastore://guides/user_follows \
--name user_follows \
--comment 'user follows table' \
--type INDEXED \
--direction BOTH \
--schema '{
    "src": {
        "type": "STRING",
        "desc": "userId"
    },
    "tgt": {
        "type": "STRING",
        "desc": "followee Id"
    },
    "fields": [
        {
          "name": "createdAt",
          "type": "LONG",
          "desc": "created at",
          "nullable": false
        }
    ]
}' \
--indices '[
    {
        "name": "created_at_desc",
        "fields": [
        {
            "name": "createdAt",
            "order": "DESC"
        }
    ],
    "desc": "order by createdAt"
    }
]'
```

Key configuration:

- `--type INDEXED` enables efficient queries by index
- `--direction BOTH` allows querying in both directions (who I follow and who follows me)
- `--indices` creates a secondary index for sorting by creation time

![Create table command](https://placehold.co/800x400/1a1a2e/eee?text=Create+Table)

#### Follow a User

**@zipdoki** follows **@j4rami**:

```bash
mutate user_follows \
--type INSERT \
--table user_follows \
--source zipdoki \
--target j4rami \
--version $(date +%s)000 \
--properties '{
    "createdAt": '$(date +%s)000'
}'
```

This creates a directed edge from `zipdoki` to `j4rami`. Actionbase precomputes counts and indices at write time, so reads are fast.

![Profile with Following button](https://placehold.co/800x400/1a1a2e/eee?text=Follow+User)

#### Query Follow Data

**Check follow status** - verify the relationship exists:

```bash
get user_follows --source zipdoki --target j4rami
```

**Count followers** - get **@j4rami**'s follower count:

```bash
count user_follows --start j4rami --direction IN
```

The `--direction IN` queries incoming edges (followers). No aggregation needed - Actionbase precomputes counts at write time.

**List followers** - get users following **@j4rami**:

```bash
scan user_follows --start j4rami --index created_at_desc --direction IN
```

Results are already indexed by `created_at_desc`, making pagination efficient.

![Followers list](https://placehold.co/800x400/1a1a2e/eee?text=Followers+List)

### Build Likes

Likes follow the same pattern as follows. A user interacts with a post instead of another user.

#### Like a Post

**@zipdoki** likes **@j4rami**'s post (post ID: 1):

```bash
mutate user_likes \
--type INSERT \
--table user_likes \
--source zipdoki \
--target 1 \
--version $(date +%s)000 \
--properties '{
    "createdAt": '$(date +%s)000'
}'
```

![Post with like button](https://placehold.co/800x400/1a1a2e/eee?text=Like+Post)

#### Query Like Status

The like is recorded:

```bash
get user_likes --source zipdoki --target 1
```

Just like follows, you can also:

- **Count likes**: `count user_likes --start 1 --direction IN`
- **List who liked**: `scan user_likes --start 1 --direction IN`

Same pattern, same simplicity.
