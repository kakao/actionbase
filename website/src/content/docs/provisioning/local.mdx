This guide provides additional local provisioning options beyond the [Quick Start](/quick-start/) guide. Use Quick Start for the fastest way to get started, or use the methods below for more control over your local environment.

## Overview

Actionbase can be run locally in two ways:

1. **Using Gradle**: Run Actionbase directly with `./gradlew`, using either in-memory storage or connecting to a local HBase instance
2. **Using Docker Compose**: Run HBase locally, then connect Actionbase using Gradle

Both approaches are suitable for local development, testing, and exploring Actionbase's capabilities.

## Prerequisites

Before getting started, ensure you have:

- **Java 17** or higher
- **Gradle 7.0+** (or use the included Gradle wrapper)
- **Docker** and **Docker Compose** (for Docker-based setup)

## Method 1: Using Gradle

The simplest way to run Actionbase locally is using Gradle. This method doesn't require Docker and is ideal for quick testing and development.

### Option A: In-Memory Storage (Default)

Actionbase includes a built-in in-memory storage implementation that requires no additional setup. This is the fastest way to get started.

**Running the Server:**

```bash
./gradlew :server:bootRun
```

The server will start on `http://localhost:8080` by default, using in-memory storage.

**Note:** Data stored in memory is not persisted. All data will be lost when the server stops. This is suitable for testing and development, but not for scenarios where you need data persistence.

### Option B: Local HBase

To use a local HBase instance with Gradle, you'll need to have HBase running locally first.

**1. Start HBase Locally**

You can run HBase using Docker Compose (see Method 2 below) or install HBase locally.

**2. Run Actionbase with Local Profile**

Once HBase is running, start Actionbase with the `local` profile:

```bash
./gradlew :server:bootRun --args='--spring.profiles.active=local'
```

This connects to HBase running on `localhost:2181` (default ZooKeeper port).

## Method 2: Using Docker Compose

Docker Compose provides a convenient way to run HBase locally, which you can then use with Actionbase. This method is useful when you want to test with persistent storage.

### Local HBase

Run HBase locally using Docker Compose:

```bash
cd dev/hbase
docker compose up
```

This starts a local HBase instance that you can use with Actionbase. The HBase instance will be available on `localhost:2181` (ZooKeeper port).

Once HBase is running, start Actionbase using Gradle with the local profile:

```bash
./gradlew :server:bootRun --args='--spring.profiles.active=local'
```

Data will be persisted in the HBase container's volumes, so your data will survive container restarts (as long as the volumes are not removed).

**Note:** The Docker Compose setup only starts HBase. You still need to run Actionbase separately using Gradle, as shown above.

## Verifying the Setup

Once the server is running, verify that Actionbase is working:

**1. Check Server Status**

The server should be available at `http://localhost:8080`. You can check if it's running:

```bash
curl http://localhost:8080/graph/health
```

**2. Using the CLI**

If you have the Actionbase CLI installed, connect to your local server. See [CLI Guide](/operations/cli/) for installation and usage details.

```bash
actionbase --host http://localhost:8080
```

**3. Using REST API**

You can also test using `curl` or any HTTP client. See the [API Reference](/api-references/query/) for detailed endpoint documentation.

## Configuration

Configuration is handled through Spring profiles:

- **Default (in-memory)**: No profile needed, uses in-memory storage
- **Local HBase**: Use `--spring.profiles.active=local` to connect to local HBase
