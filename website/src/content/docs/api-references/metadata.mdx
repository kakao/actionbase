Metadata management API for databases, tables, and aliases.

## 1. List Databases

Retrieve all databases.

### Endpoint

```
GET /graph/v3/databases
```

### Parameters

| Location | Parameter     | Required | Description                                  |
| -------- | ------------- | -------- | -------------------------------------------- |
| Header   | Authorization | Optional | Authentication key (reserved for future use) |

### Response Type

[DdlPage](#ddlpage)`<`[DatabaseResponse](#databaseresponse)`>` - Paged list of databases

### Request Example

```bash
curl -X GET \
    "http://ab.example.com/graph/v3/databases" \
    -H "Authorization: YOUR_API_KEY"
```

### Response Example

```json
{
  "count": 1,
  "content": [{ "active": true, "database": "mydb", "comment": "My database" }]
}
```

## Data Model

The v3 metadata surface is the v2 metastore shape with v3 names. Every response is flat: the table
type, direction, indexes, groups and caches sit beside `schema`, not inside it.

### DdlPage

Listing envelope, shared with the v2 API.

```kotlin
data class DdlPage<T>(
    val count: Long,          // Number of entries in `content`
    val content: List<T>,     // The entries
)
```

### DdlStatus

Mutation envelope, shared with the v2 API. `message` is omitted when null.

```kotlin
data class DdlStatus<T>(
    val status: Status,       // CREATED, UPDATED, DELETED, IDLE, ERROR, BAD_REQUEST
    val result: T?,           // The resulting entity
    val message: String?,     // Failure detail, if any
)
```

### DatabaseResponse

Database information payload.

```kotlin
data class DatabaseResponse(
    val active: Boolean,      // Whether the database is active
    val database: String,     // Database name
    val comment: String,      // Database description
)
```

### TableResponse

Table information payload. One shape for all four table types; `type` says which.

```kotlin
data class TableResponse(
    val active: Boolean,           // Whether the table is active
    val database: String,          // Database name
    val table: String,             // Table name
    val comment: String,           // Table description
    val type: TableType,           // EDGE, IMMUTABLE_EDGE, MULTI_EDGE, VERTEX
    val schema: TableSchema,       // Source, target and properties
    val direction: DirectionType,  // OUT, IN, BOTH
    val storage: String,           // Storage URI (`datastore://<namespace>/<table>`)
    val indexes: List<Index>,      // Index definitions
    val groups: List<Group>,       // Group definitions
    val caches: List<Cache>,       // Cache definitions
    val mode: MutationMode,        // SYNC, ASYNC, DROP
)
```

### AliasResponse

Alias information payload.

```kotlin
data class AliasResponse(
    val active: Boolean,      // Whether the alias is active
    val database: String,     // Database name
    val alias: String,        // Alias name
    val table: String,        // Target table name
    val comment: String,      // Alias description
)
```

### TableSchema

Schema definition, shared by every table type.

```kotlin
data class TableSchema(
    val source: Key,                  // Source key field
    val target: Key,                  // Target key field
    val properties: List<Property>,   // Property fields
)

data class Key(
    val type: VertexType,   // LONG or STRING
    val comment: String,    // Field description
)

data class Property(
    val name: String,       // Field name
    val type: DataType,     // Data type
    val nullable: Boolean,  // Whether the field is nullable (default: false)
    val comment: String,    // Field description
)
```

A **multi-edge** table carries its id as the `_id` property; a **vertex** table carries its id in
`source` and leaves `target` as a placeholder. Both follow the v2 layout exactly, so a v2 payload
converts by renaming keys and nothing else.

### Index

Index definition.

```kotlin
data class Index(
    val index: String,             // Index name
    val fields: List<IndexField>,  // Indexed fields with sort order
    val comment: String = "",      // Index description
)
```

### IndexField

Index field definition.

```kotlin
data class IndexField(
    val field: String,  // Field name
    val order: Order,   // Sort order (ASC, DESC)
)
```

### Group

Group definition for aggregation queries.

```kotlin
data class Group(
    val group: String,                              // Group name
    val type: GroupType,                            // Aggregation type (SUM, COUNT)
    val fields: List<GroupField>,                   // Group key fields
    val valueField: String = "-",                   // Value field name
    val comment: String = "",                       // Group description
    val directionType: DirectionType = BOTH,        // Direction type
    val ttl: Long = -1,                             // Time-to-live in milliseconds (-1 = no expiry)
)
```

### Cache

Cache definition. Precomputes a bounded, sorted projection of edges (e.g., top-N by score) for low-latency reads.

```kotlin
data class Cache(
    val cache: String,                              // Cache name
    val fields: List<IndexField>,                   // Sort keys with order
    val limit: Int = 100,                           // Maximum number of pre-sorted entries kept per source key (must be > 0)
    val comment: String = Constants.DEFAULT_COMMENT,// Cache description
)
```

> **Updating `indexes` / `groups` / `caches` via PUT**: each is a top-level field. Omitting one
> leaves it untouched; sending one replaces it wholesale. A table's `type` and `direction` are fixed
> at creation and cannot be changed.

### TableCreateRequest

Table creation request payload.

```kotlin
data class TableCreateRequest(
    val table: String,             // Table name
    val type: TableType,           // EDGE, IMMUTABLE_EDGE, MULTI_EDGE, VERTEX
    val schema: TableSchema,       // Source, target and properties
    val direction: DirectionType,  // OUT, IN, BOTH
    val storage: String,           // Storage URI (`datastore://<namespace>/<table>`)
    val indexes: List<Index>,      // Index definitions (default: empty)
    val groups: List<Group>,       // Group definitions (default: empty)
    val caches: List<Cache>,       // Cache definitions (default: empty)
    val mode: MutationMode,        // Mutation mode (default: SYNC)
    val comment: String,           // Table description
)
```

An `IMMUTABLE_EDGE` table accepts at most one index and cannot use `BOTH`; a `VERTEX` table must use
`OUT` and carry no index, group or cache.

### Enums

```kotlin
enum class TableType { EDGE, IMMUTABLE_EDGE, MULTI_EDGE, VERTEX }
enum class MutationMode { SYNC, ASYNC, DROP, DENY }
enum class DirectionType { BOTH, OUT, IN }
enum class VertexType { LONG, STRING }
enum class DataType { BOOLEAN, BYTE, SHORT, INT, LONG, FLOAT, DOUBLE, DECIMAL, STRING, JSON }
enum class Order { ASC, DESC }
enum class GroupType { SUM, COUNT }
```

<Aside type="note">
  All enum values are serialized **uppercase** in JSON, the same as the v2 API (e.g., `"STRING"`,
  `"INT"`, `"SYNC"`, `"OUT"`).
</Aside>

### Validation Rules

| Field                         | Rule                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| Database / Table / Alias name | `^[a-z][a-z0-9_]{0,63}$` — starts with a lowercase letter, lowercase alphanumeric/underscore |
| Storage URI                   | `^datastore://([a-z][a-z0-9_]*)?/[a-z][a-z0-9_]*$` (namespace optional)                     |
| Comment                       | Max 1000 characters                                                                          |

## V2 Compatibility

The v3 API is the v2 DDL surface with v3 names. Both dialects describe the same stored entity, so a
v2 payload becomes a v3 payload by renaming keys — the structure, the nesting and the enum values
are unchanged. `/graph/v2` stays available for backward compatibility.

### Terminology Mapping

| V2 Term | V3 Term  | Description             |
| ------- | -------- | ----------------------- |
| Service | Database | Logical database        |
| Label   | Table    | Table with edge schema  |
| Alias   | Alias    | Table alias (unchanged) |

### Field Mapping

| V2 field                  | V3 field                    | Note                                     |
| ------------------------- | --------------------------- | ---------------------------------------- |
| `name: "service.label"`   | `database` + `table`        | Split into two fields                    |
| `desc`                    | `comment`                   | At every level                           |
| `schema.src`              | `schema.source`             |                                          |
| `schema.tgt`              | `schema.target`             |                                          |
| `schema.fields`           | `schema.properties`         |                                          |
| `dirType`                 | `direction`                 | Stays top-level                          |
| `indices`                 | `indexes`                   | Stays top-level                          |
| `indices[].name`          | `indexes[].index`           |                                          |
| `indices[].fields[].name` | `indexes[].fields[].field`  |                                          |
| `indices[].desc`          | `indexes[].comment`         |                                          |
| `groups`, `caches`        | `groups`, `caches`          | Unchanged                                |
| `storage`                 | `storage`                   | Unchanged                                |
| `event`, `readOnly`       | —                           | Derived by the server, not on the surface |

### Table Type Mapping

| V2 LabelType        | V3 TableType     | Conversion                          |
| ------------------- | ---------------- | ----------------------------------- |
| INDEXED             | EDGE             | Bidirectional                       |
| IMMUTABLE_INDEXED   | IMMUTABLE_EDGE   | Bidirectional                       |
| MULTI_EDGE          | MULTI_EDGE       | Bidirectional                       |
| VERTEX              | VERTEX           | Bidirectional                       |
| HASH, NIL           | EDGE             | Read-only (V2 to V3), not creatable |

A multi-edge table keeps its id as the `_id` property and a vertex table keeps its id in `source`,
exactly as v2 stores them.

### Response Envelopes

| Operation | V2 and V3 response           |
| --------- | ---------------------------- |
| List      | `{count, content}`           |
| Mutation  | `{status, result, message}`  |
| Get one   | The entity itself            |

| V2 Endpoint                                          | V3 Endpoint                                             |

| `POST /graph/v2/service/{service}`                   | `POST /graph/v3/databases`                              |
| `PUT /graph/v2/service/{service}`                    | `PUT /graph/v3/databases/{database}`                    |
| `DELETE /graph/v2/admin/service/{service}`           | `DELETE /graph/v3/databases/{database}`                 |

| `PUT /graph/v2/service/{service}/label/{label}`      | `PUT /graph/v3/databases/{database}/tables/{table}`     |
| `DELETE /graph/v2/admin/service/{service}/label/{label}` | `DELETE /graph/v3/databases/{database}/tables/{table}` |
| `GET /graph/v2/service/{service}/alias`              | `GET /graph/v3/databases/{database}/aliases`            |
| `GET /graph/v2/service/{service}/alias/{alias}`      | `GET /graph/v3/databases/{database}/aliases/{alias}`    |
| `POST /graph/v2/service/{service}/alias/{alias}`     | `POST /graph/v3/databases/{database}/aliases`           |
| `PUT /graph/v2/service/{service}/alias/{alias}`      | `PUT /graph/v3/databases/{database}/aliases/{alias}`    |
| `DELETE /graph/v2/admin/service/{service}/alias/{alias}` | `DELETE /graph/v3/databases/{database}/aliases/{alias}` |

### MutationMode Mapping

| V2 Mode | V3 Mode | Description                            |
| ------- | ------- | -------------------------------------- |
| SYNC    | SYNC    | Synchronous mutation                   |
| ASYNC   | ASYNC   | Asynchronous mutation                  |
| IGNORE  | DROP    | Drop mutations silently                |
| -       | DENY    | Deny mutations (V3 only, throws error) |

### V3 Alias Constraints

V3 aliases can only reference tables within the same database. Cross-database aliases (supported in V2 via `database.table` format) are not available in V3.
