액션베이스의 메타데이터는 그래프 데이터베이스의 구조와 구성을 정의합니다. 데이터가 어떻게 구성되는지, 어떤 스키마가 사용되는지, 쿼리가 데이터에 어떻게 액세스하는지를 설명합니다.

## 버전 정보

액션베이스에는 두 가지 버전의 메타데이터가 있습니다: v2와 v3. 현재 **메타데이터는 v2를 사용**하며, 뮤테이션 및 쿼리 작업은 v3로 전환되었습니다. 메타데이터 v3 지원은 향후 계획되어 있지만, 현재는 모든 메타데이터 작업이 v2를 사용합니다.

## 메타데이터 개념

### Service (v3: Database)

**Service**는 레이블과 별칭을 포함하는 논리적 그룹입니다. 관련 그래프 구조에 대한 조직 및 격리를 제공합니다.

**속성:**
- **name**: 서비스 식별자
- **desc**: 서비스 설명
- **active**: 서비스 활성화 여부

서비스는 관련 레이블을 함께 그룹화하여 그래프 데이터 구조를 더 쉽게 구성하고 관리할 수 있게 합니다.

### Label (v3: Table)

**Label**은 그래프 엣지의 스키마를 정의합니다. 소스 및 타겟 노드 유형, 엣지 속성, 인덱스를 포함한 관계의 구조를 지정합니다.

**속성:**
- **name**: `service.label` 형식의 레이블 식별자
- **type**: 레이블 유형
- **schema**: 엣지의 구조 정의
  - **src**: 소스 노드 유형 및 설명
  - **tgt**: 타겟 노드 유형 및 설명
  - **fields**: 엣지 속성 목록 (이름, 유형, nullable, 설명)
- **dirType**: 방향 유형 (directed/undirected)
- **storage**: 데이터가 저장되는 스토리지 이름
- **indices**: 효율적인 쿼리를 위한 인덱스 목록
  - 각 인덱스는 이름, 필드 목록(정렬 순서 포함), 설명을 가짐
- **event**: 이벤트 활성화 여부
- **readOnly**: 레이블이 읽기 전용인지 여부
- **mode**: 뮤테이션 모드
- **active**: 레이블 활성화 여부
- **desc**: 레이블 설명

레이블은 엣지가 가질 수 있는 속성과 인덱스를 통해 쿼리할 수 있는 방법을 포함하여 엣지의 전체 스키마를 정의합니다.

### Alias (v3: Alias)

**Alias**는 레이블을 가리키는 참조입니다. 동일한 레이블에 액세스하기 위해 다른 이름을 사용할 수 있게 하여 명명 및 조직에서 유연성을 제공합니다.

**속성:**
- **name**: `service.alias` 형식의 별칭 식별자
- **target**: 이 별칭이 가리키는 레이블, `service.label` 형식
- **desc**: 별칭 설명
- **active**: 별칭 활성화 여부

별칭을 사용하면 다른 이름으로 레이블을 참조할 수 있어 데이터 구조를 더 쉽게 구성하고 액세스할 수 있습니다.

### Storage

**Storage**는 데이터의 물리적 스토리지 구성을 정의합니다. 기본 스토리지 백엔드(예: HBase)에 데이터가 저장되는 방식을 지정합니다.

**속성:**
- **type**: 스토리지 유형
- **name**: 스토리지 식별자
- **desc**: 스토리지 설명
- **active**: 스토리지 활성화 여부
- **conf**: 스토리지별 설정이 포함된 구성 맵

레이블은 이름으로 스토리지를 참조하여 데이터가 물리적으로 저장되는 위치를 결정합니다.

## 메타데이터 계층 구조

메타데이터 구조는 다음 계층을 따릅니다:

```
Service
├── Label (스키마 정의)
│   ├── Schema (src, tgt, fields)
│   ├── Indices (쿼리용)
│   └── Storage (물리적 스토리지)
└── Alias (Label을 가리킴)
```

- **Service**는 여러 **Label**과 **Alias**를 포함합니다
- **Label**은 엣지의 스키마와 인덱스를 정의합니다
- **Alias**는 **Label**을 가리켜 대체 이름을 허용합니다
- **Label**은 물리적 데이터 저장을 위해 **Storage**를 참조합니다

## 명명 규칙

### Service
- 간단한 식별자: `myservice`

### Label
- 형식: `service.label`
- 예제: `myservice.follows`, `myservice.likes`

### Alias
- 형식: `service.alias`
- 예제: `myservice.friends` (`myservice.follows`를 가리킴)

### Storage
- 간단한 식별자: `hbase-storage-1`

## 스키마 정의

레이블은 `schema` 속성을 통해 엣지의 스키마를 정의합니다:

- **src**: 소스 노드 유형 (예: STRING, LONG)
- **tgt**: 타겟 노드 유형 (예: STRING, LONG)
- **fields**: 엣지 속성 목록
  - 각 필드는 이름, 유형, nullable 플래그, 설명을 가짐

이 스키마 정의는 엣지에 저장할 수 있는 데이터와 구조를 결정합니다.

## 인덱스

레이블은 효율적인 쿼리를 가능하게 하는 인덱스를 정의합니다. 각 인덱스는:

- 레이블 내에서 고유한 이름을 가짐
- 인덱스할 필드 목록을 지정
- 각 필드는 정렬 순서(ASC/DESC)를 가짐
- 설명을 포함

인덱스는 Scan 쿼리에서 속성 값을 기반으로 엣지를 효율적으로 조회하는 데 사용됩니다. 인덱스 구조는 쿼리가 데이터를 필터링하고 정렬할 수 있는 방법을 결정합니다.

## 메타데이터와 쿼리

메타데이터는 쿼리 작동 방식에 직접적인 영향을 미칩니다:

- **Label 스키마**는 엣지가 가질 수 있는 속성을 정의합니다
- **인덱스**는 가능하고 효율적인 Scan 쿼리를 결정합니다
- **Storage** 구성은 데이터가 물리적으로 저장되고 조회되는 위치에 영향을 미칩니다

뮤테이션을 수행하면 데이터 구조는 레이블의 스키마를 따릅니다. 쿼리를 수행하면 레이블의 메타데이터에 정의된 인덱스를 사용해야 합니다. 메타데이터와 쿼리 간의 이러한 명시적 관계는 쿼리가 스키마 정의 중에 준비된 최적화된 경로를 따르도록 보장합니다.
