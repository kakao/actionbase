액션베이스는 검증된 스토리지 기술 위에 구축되어, 그래프 데이터 모델과 쓰기 시점 최적화를 통해 자체 가치를 추가하면서 그들의 강점을 활용합니다. 데이터스토어 추상화 레이어를 통해 액션베이스는 다양한 스토리지 백엔드와 통합할 수 있으며, 각각 고유한 특성과 기능을 제공합니다.

## 데이터스토어 추상화

액션베이스는 데이터스토어 인터페이스를 통해 스토리지 작업을 추상화하여 다양한 스토리지 백엔드와 함께 작동할 수 있습니다. 검증된 스토리지 기술 위에 구축함으로써, 액션베이스는 그래프 특화 기능 제공에 집중하면서 그들의 검증된 신뢰성, 확장성 및 성능 특성을 활용할 수 있습니다.

선택한 데이터스토어의 특성은 액션베이스의 동작 방식에 직접적인 영향을 미치며, 각 데이터스토어는 고유한 강점을 제공합니다. 액션베이스는 스토리지 기능을 재발명하기보다는 각 스토리지 백엔드의 강점과 함께 작동하도록 설계되었습니다.

### 필수 작업

데이터스토어는 액션베이스와 호환되려면 다음 작업을 지원해야 합니다:

- **get**: 키로 단일 값을 조회하거나, 키 목록으로 여러 값을 조회
- **delete**: 키로 값 삭제
- **scan**: prefix, start, stop, limit 파라미터를 사용한 범위 스캔 수행
- **checkAndMutate**: 일관성 보장을 위한 원자적 체크-앤-뮤테이트 작업 (잠금 또는 낙관적 동시성 제어에 사용)
- **batch**: 배치 뮤테이션 작업 (선택 사항이지만 효율성을 위해 권장)

이 인터페이스는 의도적으로 최소한으로 설계되었습니다. 스토리지 백엔드가 이러한 작업을 구현하는 한, 액션베이스와 통합할 수 있으며, 액션베이스가 스토리지 백엔드의 기존 기능과 최적화를 활용할 수 있습니다.

## 지원되는 데이터스토어

### Memory

**Memory**는 개발 및 테스트를 위해 설계된 인메모리 데이터스토어입니다.

**특성:**
- **사용하기 쉬움**: 설정이 필요 없으며, 빠른 개발 및 테스트에 완벽함
- **영속성 없음**: 데이터가 디스크에 저장되지 않으며 서버가 중지되면 손실됨
- **빠름**: 인메모리 작업으로 매우 낮은 지연 시간 제공

Memory 데이터스토어는 데이터 영속성이 필요하지 않은 로컬 개발, 테스트 및 빠른 프로토타이핑에 이상적입니다.

### HBase

**HBase**는 현재 액션베이스에서 프로덕션 데이터스토어로 사용됩니다. Hadoop 분산 파일 시스템(HDFS) 위에 구축된 분산형 컬럼 지향 NoSQL 데이터베이스로, 대규모 데이터 저장 및 실시간 액세스를 위해 설계되었습니다.

**특성:**
- **수평 확장**: 데이터를 여러 노드에 자동으로 분산하여 데이터 증가에 따라 원활하게 확장 가능
- **저지연 랜덤 액세스**: 낮은 지연 시간으로 랜덤 읽기 및 쓰기에 최적화
- **내장 복제**: 네이티브 복제 기능으로 고가용성 및 읽기 복제본을 통한 읽기 확장 가능
- **벌크 작업**: 초기 데이터 수집을 위한 효율적인 벌크 로딩 기능
- **성숙한 생태계**: 광범위한 도구 및 커뮤니티 지원을 갖춘 Hadoop 생태계의 일부

HBase는 일관된 성능으로 페타바이트 규모의 데이터를 처리해야 하는 프로덕션 환경에 적합합니다. 많은 대규모 조직에서 대규모로 검증되었습니다. 액션베이스는 HBase의 검증된 확장성, 강력한 일관성 모델 및 성숙한 운영 도구를 활용하여 대규모 그래프 데이터베이스 기능을 제공합니다.

### SlateDB

**SlateDB**는 중소규모 배포를 위한 더 가벼운 대안을 제공하기 위해 설계된 계획된 데이터스토어 옵션입니다.

**특성:**
- **낮은 운영 복잡도**: 대규모 분산 시스템에 비해 더 간단한 설정 및 유지보수
- **리소스 효율성**: HBase의 전체 인프라 오버헤드가 필요하지 않은 배포에 최적화
- **트랜잭션 지원**: 중소규모 워크로드에 적합한 트랜잭션 보장 제공
- **쉬운 배포**: 인프라 요구사항 감소로 제한된 운영 리소스를 가진 팀에게 더 접근 가능
- **비용 효율적**: HBase의 전체 규모 기능이 필요하지 않은 배포에 대해 낮은 운영 비용

HBase는 매우 큰 규모에서 뛰어나지만 상당한 운영 오버헤드와 인프라 요구사항이 있습니다. 페타바이트 규모의 데이터를 처리할 필요가 없는 배포의 경우, 이 오버헤드는 채택의 장벽이 될 수 있습니다. SlateDB는 이러한 사용 사례에 대해 더 접근 가능한 옵션을 제공하기 위해 개발 중이며, 동일한 그래프 데이터베이스 기능을 유지하면서 액션베이스가 더 넓은 범위의 배포 시나리오를 지원할 수 있도록 합니다.

## 액션베이스가 데이터스토어 작업을 사용하는 방법

액션베이스는 이러한 데이터스토어 작업을 사용하여 핵심 기능을 구현합니다:

- **get**: Get 쿼리에서 엣지 상태를 조회하는 데 사용
- **scan**: Scan 쿼리에서 인덱스 항목을 조회하는 데 사용
- **checkAndMutate**: 뮤테이션 중 잠금을 획득하고 원자성을 보장하는 데 사용
- **batch**: 지원되는 경우 여러 뮤테이션(상태, 인덱스, 카운터)을 원자적으로 효율적으로 쓰는 데 사용
- **delete**: 뮤테이션 중 이전 인덱스 항목을 제거하는 데 사용

검증된 스토리지 기술 위에 구축하고 그들의 기능을 활용함으로써, 액션베이스는 쓰기 시점 최적화, 효율적인 그래프 쿼리, 유연한 스키마 진화와 같은 그래프 특화 기능 제공에 집중할 수 있으며, 기본 스토리지는 데이터 영속성, 복제 및 확장성의 복잡성을 처리합니다.
