## 일반 질문

### 액션베이스란 무엇인가요?

액션베이스는 대규모로 사용자 활동 데이터를 효율적으로 저장하고 쿼리하기 위해 설계된 프로덕션 검증된 OLTP 그래프 데이터베이스입니다. 그래프 데이터 모델을 사용하며 초고속 읽기를 위한 쓰기 시점 최적화를 제공합니다.

### 액션베이스는 어떤 문제를 해결하나요?

액션베이스는 대규모 사용자 활동 데이터를 다룰 때 MySQL과 같은 단일 RDB 시스템의 한계를 해결합니다. OLTP 성능을 유지하면서 복잡한 샤딩 로직을 단순화하고 5ms 미만의 읽기 지연 시간을 제공합니다.

### 액션베이스는 프로덕션 준비가 되어 있나요?

네. 액션베이스는 카카오톡 및 카카오쇼핑을 포함한 여러 주요 [카카오](/ko/about-kakao) 서비스를 지원하며, 실시간 활동 데이터 처리를 통해 수천만 명의 사용자에게 서비스를 제공합니다.

## 기술 질문

### 액션베이스는 어떤 스토리지 백엔드를 지원하나요?

현재 액션베이스는 스토리지 레이어로 HBase를 사용합니다. 향후 릴리스에서는 SlateDB를 포함한 추가 스토리지 백엔드를 지원할 예정입니다.

### 쓰기 시점 최적화란 무엇인가요?

쓰기 시점 최적화는 액션베이스가 쓰기 중에 인덱스와 카운터를 사전 계산하여 비용이 많이 드는 쿼리 시점 계산 없이 초고속 읽기를 가능하게 한다는 의미입니다. 이를 통해 일관된 저지연 읽기 작업(&lt;5ms p99)을 제공합니다.

### 액션베이스는 Neo4j와 어떻게 비교되나요?

Neo4j가 광범위한 그래프 데이터베이스 문제를 해결하려는 반면, 액션베이스는 특정 하위 집합인 사용자 활동 데이터 처리에 집중합니다. 액션베이스는 확장성 및 벌크 로딩 기능을 포함한 HBase의 모든 강점을 활용하면서 그 위에 개선된 사용성을 제공합니다. HBase를 사용하면 더 쉬운 사용성과 함께 HBase의 이점을 얻을 수 있으며, SlateDB(계획됨)를 사용하면 동일한 일관된 인터페이스와 함께 SlateDB의 이점을 얻을 수 있습니다.

### 어떤 프로그래밍 언어가 지원되나요?

액션베이스 모듈은 다음으로 구축됩니다:
- **핵심 모듈**: Java, Kotlin (Java 8)
- **Engine 및 Server**: Kotlin (Java 17)
- **Pipeline**: Scala (Java 8)

## 시작하기

## 성능

### 어떤 종류의 성능을 기대할 수 있나요?

프로덕션 환경에서 액션베이스는 다음을 달성합니다:
- 읽기 지연 시간: &lt;5ms (p99)
- 처리량: 초당 수십만 건의 요청
- 데이터 규모: 다중 TB 규모 배포

### 액션베이스는 수평 확장을 어떻게 처리하나요?

액션베이스는 수평 확장을 위해 설계되었습니다. HBase와 같은 기본 스토리지 백엔드의 확장성을 활용하면서 분산 데이터 관리를 위한 통합 인터페이스를 제공합니다.
