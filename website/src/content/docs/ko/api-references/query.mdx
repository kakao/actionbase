엣지 테이블(EdgeTable)은 세 가지 유형의 엣지 쿼리를 지원합니다: count, get, scan.

## 1. Count

특정 노드에서 시작하는 엣지의 개수를 조회합니다.

### 엔드포인트

```
GET /graph/v3/databases/{database}/tables/{table}/edges/count
```

### 파라미터

| 위치 | 파라미터 | 필수 | 설명 |
|----------|-----------|----------|-------------|
| Header | Authorization | 필수 | 인증 키 (API 키) |
| Path | database | 필수 | 대상 데이터베이스 이름 |
| Path | table | 필수 | 대상 테이블 이름 |
| Query | start | 필수 | 시작 노드 ID |
| Query | direction | 필수 | [쿼리 방향](#쿼리-방향) (OUT 또는 IN) |
| Query | ranges | 선택 (기본값: null) | [스캔 범위](#인덱스-범위) |

### 응답 타입

[Count](#count-응답) - 엣지 개수 정보를 포함하는 페이로드

### 요청 예제

| 파라미터 | 값 |
|-----------|-------|
| Authorization | YOUR_API_KEY |
| database | your_database |
| table | your_table |
| start | source1 |
| direction | OUT |

```bash
# count?start=source1&direction=OUT
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/count?start=source1&direction=OUT" \
    -H "Authorization: YOUR_API_KEY"
```

### 응답 예제

```json
{
  "start": "source1",
  "direction": "OUT",
  "count": 10,
  "context": {}
}
```

## 2. Get

소스 노드와 타겟 노드 사이의 엣지를 조회합니다.

### 엔드포인트

```
GET /graph/v3/databases/{database}/tables/{table}/edges/get
```

### 파라미터

| 위치 | 파라미터 | 필수 | 설명 |
|----------|-----------|----------|-------------|
| Header | Authorization | 필수 | 인증 키 (API 키) |
| Path | database | 필수 | 대상 데이터베이스 이름 |
| Path | table | 필수 | 대상 테이블 이름 |
| Query | source | 필수 | 소스 노드 ID 목록 (쉼표로 구분) |
| Query | target | 필수 | 타겟 노드 ID 목록 (쉼표로 구분) |
| Query | filters | 선택 (기본값: null) | [필터링 조건](#필터) |

여러 소스 또는 타겟 ID가 지정되면, 이 작업은 여러 엣지를 조회하는 **mget**으로 동작합니다. 이 경우 API 요청당 최대 **25개의 엣지**를 조회할 수 있습니다. 더 많은 엣지를 조회하려면 여러 번의 API 요청을 해야 합니다.

### 응답 타입

[EdgeFrame](#edgeframe-응답) - 엣지 데이터를 포함하는 페이로드

### 요청 예제 (Get) - 1개 소스, 1개 타겟

(source, target)에 대한 엣지 데이터를 조회합니다. (최대 1개 결과)

| 파라미터 | 값 |
|-----------|-------|
| Authorization | YOUR_API_KEY |
| database | your_database |
| table | your_table |
| source | source1 |
| target | target1 |

```bash
# get?source=source1&target=target1
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/get?source=source1&target=target1" \
    -H "Authorization: YOUR_API_KEY"
```

**응답:**

```json
{
  "edges": [
    {
      "version": 1,
      "source": "source1",
      "target": "target1",
      "properties": {
        "weight": 0.8,
        "type": "FOLLOWS"
      },
      "context": {}
    }
  ],
  "count": 1,
  "total": 1,
  "offset": null,
  "hasNext": false,
  "context": {}
}
```

## 3. Scan

인덱스를 사용하여 엣지를 스캔합니다.

### 엔드포인트

```
GET /graph/v3/databases/{database}/tables/{table}/edges/scan/{index}
```

### 파라미터

| 위치 | 파라미터 | 필수 | 설명 |
|----------|-----------|----------|-------------|
| Header | Authorization | 필수 | 인증 키 (API 키) |
| Path | database | 필수 | 대상 데이터베이스 이름 |
| Path | table | 필수 | 대상 테이블 이름 |
| Path | index | 필수 | 사용할 인덱스 이름 |
| Query | start | 필수 | 시작 노드 ID |
| Query | direction | 필수 | [쿼리 방향](#쿼리-방향) (OUT 또는 IN) |
| Query | limit | 선택 (기본값: 25) | 반환할 최대 결과 수 |
| Query | offset | 선택 (기본값: null) | [페이지네이션](#페이지네이션) 오프셋 |
| Query | ranges | 선택 (기본값: null) | [스캔 범위](#인덱스-범위) |
| Query | filters | 선택 (기본값: null) | [필터링 조건](#필터) |
| Query | features | 선택 (기본값: 빈 목록) | 포함할 기능 목록 (예: `total`을 지정하면 총 개수를 계산) |

### 응답 타입

[EdgeFrame](#edgeframe-응답) - 엣지 데이터를 포함하는 페이로드

### 요청 예제

| 파라미터 | 값 |
|-----------|-------|
| Authorization | YOUR_API_KEY |
| database | your_database |
| table | your_table |
| index | your_index |
| start | source1 |
| direction | OUT |

```bash
# scan/your_index?start=source1&direction=OUT
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/scan/your_index?start=source1&direction=OUT" \
    -H "Authorization: YOUR_API_KEY"
```

### 응답 예제

```json
{
  "edges": [
    {
      "version": 1,
      "source": "source1",
      "target": "target1",
      "properties": {
        "weight": 0.8,
        "type": "FOLLOWS"
      },
      "context": {}
    }
  ],
  "count": 1,
  "total": -1,
  "offset": null,
  "hasNext": false,
  "context": {}
}
```

**참고:** `total`이 -1이면 총 개수가 계산되지 않았습니다. `features=total`을 제공하면 총 개수가 실제로 계산됩니다.

| table | your_table | |
| index | your_index | |
| start | source1 | |
| direction | OUT | |
| limit | | 기본값: 25 |

```bash
# scan/your_index?start=source1&direction=OUT

    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/scan/your_index?start=source1&direction=OUT" \
```

**응답:**

```json

  "edges": [
    {
      "version": 1,
      "source": "source1",
      "target": "target1",
```

## 인덱스 범위

`ranges` 파라미터를 사용하여 count/scan 쿼리에서 데이터 스캔 범위를 지정할 수 있습니다.

### 범위와 인덱스의 관계

> **중요:** 범위는 인덱스에 포함된 필드만 사용할 수 있습니다.

1. **인덱스 의존성:** `ranges`에서 사용하는 필드는 인덱스가 있어야 합니다. 인덱스가 없는 필드에 범위를 지정하면 예상치 못한 결과가 반환됩니다.
2. **연산자 의미:** `eq`, `gt(e)`, `lt(e)`, `between` 연산자는 실제 스토리지 스캔의 시작점과 끝점을 결정합니다. 인덱스 속성에 따라 적절하게 사용해야 합니다.
   - 인덱스가 `DESC`(내림차순)로 설정된 경우: `lt`가 시작점이 되고 `gt`가 끝점이 됩니다.
   - 인덱스가 `ASC`(오름차순)로 설정된 경우: `gt`가 시작점이 되고 `lt`가 끝점이 됩니다.
3. **복합 범위:** 범위는 인덱스가 정의된 필드 조합의 순서대로 사용할 수 있습니다. 범위는 인덱스에 정의된 필드 순서대로 적용되어야 합니다.

### 범위 구문

범위는 다음 형식으로 작성합니다:

```
ranges=range1[;range2;range3;...]
```

각 범위는 다음 형식을 따릅니다:

```
field:operator:value
```

여러 범위를 적용하려면 세미콜론(`;`)으로 구분합니다:

```
field1:operator1:value1;field2:operator2:value2
```

`in` 또는 `bt`(between) 연산자를 사용할 때는 여러 값을 쉼표(`,`)로 구분합니다:

```
field:in:value1,value2,value3
field:bt:minValue,maxValue
```

### 연산자

| 연산자 | 설명 | 예제 |
|----------|-------------|---------|
| `eq` | 같음 | `type:eq:0` |
| `gt` | 보다 큼 | `createdAt:gt:1000000` |
| `gte` | 크거나 같음 | `createdAt:gte:1000000` |
| `lt` | 보다 작음 | `createdAt:lt:2000000` |
| `lte` | 작거나 같음 | `createdAt:lte:2000000` |
| `bt` | 두 값 사이 | `createdAt:bt:1000000,2000000` |

### 예제

**단순 범위:**

```
GET .../scan/your_index?start=10&direction=OUT&ranges=type:eq:0
```

이 예제는 `type` 속성이 0인 엣지만 조회하는 범위를 지정합니다. `type`은 `properties.type`을 의미하며, `properties.type`은 `your_index`에 포함되어 있어야 합니다.

**복합 범위:**

```
GET .../scan/your_index?start=10&direction=OUT&ranges=type:eq:0;createdAt:gt:1000000
```

이 예제는 `type`이 0이고 `createdAt`이 1000000보다 큰 엣지만 조회하는 범위를 지정합니다.

**Between 연산자:**

```
GET .../scan/your_index?start=10&direction=OUT&ranges=createdAt:bt:1000000,2000000
```

이 예제는 `createdAt`이 1000000과 2000000 사이인 엣지만 조회하는 범위를 지정합니다.

## 필터

`filters` 파라미터를 사용하여 get/scan 쿼리에서 데이터(엣지)를 필터링할 수 있습니다. [범위](#인덱스-범위)와 동일한 형식을 사용합니다.

**범위와의 차이:** [범위](#인덱스-범위)는 쿼리 범위를 사전에 지정하며 인덱스로 설정된 필드만 사용할 수 있지만, `filters`는 쿼리 결과를 필터링하며 인덱스로 설정되지 않은 필드도 사용할 수 있습니다.

### 필터 예제

```
GET .../get?source=1,2,3&target=10&filters=type:eq:0
GET .../scan/your_index?start=1&direction=OUT&ranges=createdAt:gte:1000000&filters=type:eq:0
```

## 데이터 모델

### 쿼리 방향

- **OUT:** 나가는 방향 (예: 사용자 [좋아요]→ 제품 관계에서 사용자가 좋아한 제품 조회)
- **IN:** 들어오는 방향 (예: 위 관계에서 제품을 좋아한 사용자 조회)

### Count 응답

Count 쿼리 응답. 엣지 개수 정보를 포함하는 페이로드.

```kotlin
data class Count(
  val start: Any,                 // 시작 노드 ID
  val direction: Direction,       // 방향 (IN, OUT)
  val count: Long,                // 엣지 개수
  val context: Map<String, Any?>, // 컨텍스트 정보
)
```

### EdgeFrame 응답

Get 및 Scan 쿼리 응답. 엣지 데이터를 포함하는 페이로드.

```kotlin
data class EdgeFrame(
  val edges: List<Edge>,          // 엣지 목록
  val count: Int,                 // 현재 반환된 엣지 수
  val total: Long,                // 전체 엣지 개수 (-1은 계산되지 않음을 의미)
  val offset: String?,            // 페이지네이션 오프셋
  val hasNext: Boolean,           // 다음 페이지 존재 여부
  val context: Map<String, Any?>, // 컨텍스트 정보
)
```

### Edge

개별 엣지 정보 페이로드.

```kotlin
data class Edge(
  val version: Long,                 // 엣지 버전
  val source: Any,                   // 소스 노드 ID
  val target: Any,                   // 타겟 노드 ID
  val properties: Map<String, Any?>, // 엣지 속성
  val context: Map<String, Any?>,    // 컨텍스트 정보
```
