엣지 쿼리 API (unique-edge). unique-edge와 multi-edge의 차이는 [FAQ](/ko/faq/#what-is-the-difference-between-unique-edge-and-multi-edge)를 참조하세요. 개념적 배경은 [쿼리](/ko/design/query/)를 참조하세요.

## 1. 개수 {#1-count}

특정 노드에서 시작하는 엣지의 개수를 조회합니다.

### 엔드포인트 {#endpoint}

```
GET /graph/v3/databases/{database}/tables/{table}/edges/count
```

### 파라미터 {#parameters}

| 위치 | 파라미터      | 필수 여부               | 설명                                        |
| ---- | ------------- | ----------------------- | ------------------------------------------- |
| 헤더 | Authorization | 선택 사항               | 인증 키(향후 사용을 위해 예약됨)            |
| 경로 | database      | 필수                    | 대상 데이터베이스 이름                      |
| 경로 | table         | 필수                    | 대상 테이블 이름                            |
| 쿼리 | start         | 필수                    | 시작 노드 ID                                |
| 쿼리 | direction     | 필수                    | [쿼리 방향](#query-direction) (OUT 또는 IN) |
| 쿼리 | ranges        | 선택 사항(기본값: null) | [스캔 범위](#index-ranges)                  |

### 응답 형식 {#response-type}

[개수](#count-response) - 엣지 개수 정보가 포함된 페이로드

### 요청 예시 {#request-example}

| 파라미터     | 값            |
| ------------ | ------------- |
| 권한 부여    | YOUR_API_KEY  |
| 데이터베이스 | your_database |
| 테이블       | your_table    |
| 시작         | source1       |
| 방향         | OUT           |

```bash
# count?start=source1&direction=OUT {#countstartsource1directionout}
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/count?start=source1&direction=OUT" \
    -H "Authorization: YOUR_API_KEY"
```

### 응답 예시 {#response-example}

```json
{
  "start": "source1",
  "direction": "OUT",
  "count": 10,
  "context": {}
}
```

## 2. 가져오기 {#2-get}

소스 노드와 타겟 노드 사이의 엣지를 검색합니다.

### 엔드포인트 {#endpoint}

```
GET /graph/v3/databases/{database}/tables/{table}/edges/get
```

### 매개변수 {#parameters}

| 위치 | 매개변수     | 필수 여부               | 설명                              |
| ---- | ------------ | ----------------------- | --------------------------------- |
| 헤더 | 권한 부여    | 선택 사항               | 인증 키 (향후 사용을 위해 예약됨) |
| 경로 | 데이터베이스 | 필수                    | 대상 데이터베이스 이름            |
| 경로 | 테이블       | 필수                    | 대상 테이블 이름                  |
| 쿼리 | 소스         | 필수                    | 소스 노드 ID 목록(쉼표로 구분)    |
| 쿼리 | 타겟         | 필수                    | 타겟 노드 ID 목록(쉼표로 구분)    |
| 쿼리 | 필터         | 선택 사항(기본값: null) | [필터링 조건](#filters)           |

여러 소스 또는 타겟 ID가 지정된 경우, 이 작업은 **mget**처럼 동작하여 여러 엣지를 검색합니다. 이 경우, API 요청당 최대 **25개의 엣지**만 검색할 수 있습니다. 더 많은 엣지를 검색하려면 여러 번의 API 요청을 수행해야 합니다.

### 응답 형식 {#response-type}

[EdgeFrame](#edgeframe-response) - 엣지 데이터를 포함하는 페이로드

### 요청 예시 (Get) - 1 소스, 1 타겟 {#request-example-get-1-source-1-target}

(소스, 타겟)에 대한 엣지 데이터를 조회합니다. (최대 1개의 결과)

| 파라미터      | 값            |
| ------------- | ------------- |
| Authorization | YOUR_API_KEY  |
| database      | your_database |
| table         | your_table    |
| source        | source1       |
| target        | target1       |

```bash
# get?source=source1&target=target1 {#getsourcesource1targettarget1}
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/get?source=source1&target=target1" \
    -H "Authorization: YOUR_API_KEY"
```

**Response:**

```json
{
  "edges": [
    {
      "version": 1,
      "source": "source1",
      "target": "target1",
      "properties": {
        "weight": 0.8,
        "type": "FOLLOWS"
      },
      "context": {}

  "total": 1,
  "offset": null,
  "hasNext": false,
  "context": {}
```

## 3. 스캔 {#3-scan}

인덱스를 사용하여 엣지를 스캔합니다.

### 엔드포인트 {#endpoint}

```
GET /graph/v3/databases/{database}/tables/{table}/edges/scan/{index}
```

### 파라미터 {#parameters}

| 위치 | 파라미터      | 필수 여부                     | 설명                                                |
| ---- | ------------- | ----------------------------- | --------------------------------------------------- |
| 헤더 | Authorization | 선택 사항                     | 인증 키 (향후 사용을 위해 예약됨)                   |
| 경로 | database      | 필수                          | 대상 데이터베이스 이름                              |
| 경로 | table         | 필수                          | 대상 테이블 이름                                    |
| 경로 | index         | 필수                          | 사용할 인덱스 이름                                  |
| 쿼리 | start         | 필수                          | 시작 노드 ID                                        |
| 쿼리 | direction     | 필수                          | [쿼리 방향](#query-direction) (OUT 또는 IN)         |
| 쿼리 | limit         | 선택 사항 (기본값: 25)        | 반환할 최대 결과 수; 운영 환경에서는 25를 권장      |
| 쿼리 | offset        | 선택 사항 (기본값: null)      | [페이징](#pagination) 오프셋                        |
| 쿼리 | ranges        | 선택 사항 (기본값: null)      | [스캔 범위](#index-ranges)                          |
| 쿼리 | filters       | 선택 사항 (기본값: null)      | [필터링 조건](#filters)                             |
| 쿼리 | features      | 선택 사항 (기본값: 빈 리스트) | 포함할 피처 목록 (예: `total`을 지정하면 총합 계산) |

### 응답 타입 {#response-type}

[EdgeFrame](#edgeframe-response) - 엣지 데이터를 포함하는 페이로드

### 요청 예시 {#request-example}

| 파라미터     | 값            |
| ------------ | ------------- |
| 권한 부여    | YOUR_API_KEY  |
| 데이터베이스 | your_database |
| 테이블       | your_table    |
| 인덱스       | your_index    |
| 시작         | source1       |
| 방향         | OUT           |

```bash
# scan/your_index?start=source1&direction=OUT {#scanyour-indexstartsource1directionout}
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/scan/your_index?start=source1&direction=OUT" \
    -H "Authorization: YOUR_API_KEY"
```

### 응답 예시 {#response-example}

```json
{
  "edges": [
    {
      "version": 1,
      "source": "source1",
      "target": "target1",
      "properties": {
        "weight": 0.8,
        "type": "FOLLOWS"
      },
      "context": {}
    }
  ],
  "count": 1,
  "total": -1,
  "offset": null,
  "hasNext": false,
  "context": {}
}
```

**Note:** When `total` is -1, the total count is not calculated. If `features=total` is provided, the total is actually calculated.

## 페이지네이션 {#pagination}

`offset` 매개변수는 다음 페이지의 시작 위치를 나타내며, `hasNext`는 다음 페이지가 있는지 여부를 나타냅니다. offset이 없으면 첫 번째 페이지가 반환됩니다.

offset 없이 첫 번째 페이지를 요청합니다.

| 매개변수     | 값            | 설명    |
| ------------ | ------------- | ------- |
| 권한 부여    | YOUR_API_KEY  |         |
| 데이터베이스 | your_database |         |
| 테이블       | your_table    |         |
| 인덱스       | your_index    |         |
| 시작         | source1       |         |
| 방향         | OUT           |         |
| limit        |               | 25 권장 |

```bash
# scan/your_index?start=source1&direction=OUT {#scanyour-indexstartsource1directionout}
curl -X GET \
    "http://ab.example.com/graph/v3/databases/your_database/tables/your_table/edges/scan/your_index?start=source1&direction=OUT" \
    -H "Authorization: YOUR_API_KEY"
```

**Response:**

```json
{
  "edges": [
    {
      "version": 1,
      "source": "source1",
      "target": "target1",
      "properties": {
        "weight": 0.8,
```

## 인덱스 범위 {#index-ranges}

`ranges` 매개변수를 사용하면 카운트/스캔 쿼리에서 데이터 스캔 범위를 지정할 수 있습니다.

### 범위와 인덱스의 관계 {#relationship-between-ranges-and-indexes}

> **중요:** 범위는 인덱스에 포함된 필드에만 사용할 수 있습니다.

1. **인덱스 의존성:** `ranges`에 사용되는 필드는 반드시 인덱스가 있어야 합니다. 인덱스가 없는 필드에 범위를 지정하면 예기치 않은 결과가 반환됩니다.
2. **연산자 의미:** `eq`, `gt(e)`, `lt(e)`, `between` 연산자는 실제 스토리지 스캔의 시작점과 끝점을 결정합니다. 인덱스 속성에 맞게 적절하게 사용해야 합니다.
   - 인덱스가 `DESC`(내림차순)로 설정된 경우: `lt`가 시작점이 되고 `gt`가 끝점이 됩니다.
   - 인덱스가 `ASC`(오름차순)로 설정된 경우: `gt`가 시작점이 되고 `lt`가 끝점이 됩니다.
3. **복합 범위:** 범위는 인덱스에 정의된 필드 조합의 순서로 사용할 수 있습니다. 범위는 인덱스에 정의된 필드 순서대로 적용해야 합니다.

### 범위 구문 {#range-syntax}

범위는 다음 형식으로 작성됩니다:

```
ranges=range1[;range2;range3;...]
```

각 범위는 다음 형식을 따릅니다:

```
field:operator:value
```

여러 범위를 적용하려면 세미콜론(`;`)으로 구분합니다:

```
field1:operator1:value1;field2:operator2:value2
```

`in` 또는 `bt`(사이) 연산자를 사용할 때는 여러 값을 쉼표(`,`)로 구분합니다:

```
field:in:value1,value2,value3
field:bt:minValue,maxValue
```

### 연산자 {#operators}

| 연산자 | 설명       | 예시                           |
| ------ | ---------- | ------------------------------ |
| `eq`   | 같음       | `type:eq:0`                    |
| `gt`   | 초과       | `createdAt:gt:1000000`         |
| `gte`  | 이상       | `createdAt:gte:1000000`        |
| `lt`   | 미만       | `createdAt:lt:2000000`         |
| `lte`  | 이하       | `createdAt:lte:2000000`        |
| `bt`   | 두 값 사이 | `createdAt:bt:1000000,2000000` |

### 예시 {#examples}

**단순 범위:**

```
GET .../scan/your_index?start=10&direction=OUT&ranges=type:eq:0
```

이 예시는 `type` 프로퍼티가 0인 엣지만 조회하도록 범위를 지정합니다. 이때 `type`은 `properties.type`을 의미하며, `properties.type`은 `your_index`에 포함되어야 합니다.

**복합 범위:**

```
GET .../scan/your_index?start=10&direction=OUT&ranges=type:eq:0;createdAt:gt:1000000
```

이 예시는 `type`이 0이고 `createdAt`이 1000000보다 큰 엣지만 조회하는 범위를 지정합니다.

**사이 연산자:**

```
GET .../scan/your_index?start=10&direction=OUT&ranges=createdAt:bt:1000000,2000000
```

이 예시는 `createdAt`이 1000000과 2000000 사이인 엣지만 조회하는 범위를 지정합니다.

## 필터 {#filters}

`filters` 매개변수를 사용하면 get/scan 쿼리에서 데이터(엣지)를 필터링할 수 있습니다. [범위](#index-ranges)와 동일한 형식을 사용합니다.

**범위와의 차이점:** [범위](#index-ranges)는 쿼리 범위를 미리 지정하며 인덱스로 설정된 필드만 사용할 수 있지만, `filters`는 쿼리 결과를 필터링하며 인덱스로 설정되지 않은 필드도 사용할 수 있습니다.

### 필터 예시 {#filter-examples}

```
GET .../get?source=1,2,3&target=10&filters=type:eq:0
GET .../scan/your_index?start=1&direction=OUT&ranges=createdAt:gte:1000000&filters=type:eq:0
```

## 데이터 모델 {#data-model}

### 쿼리 방향 {#query-direction}

- **OUT:** 나가는 방향(예: 사용자 [좋아요]→ 상품 관계에서 사용자가 좋아요한 상품 조회)
- **IN:** 들어오는 방향(예: 위의 관계에서 상품을 좋아요한 사용자 조회)

### 카운트 응답 {#count-response}

엣지 개수 정보를 포함하는 페이로드입니다.

```kotlin
data class Count(
  val start: Any,                 // Starting node ID
  val direction: Direction,       // Direction (IN, OUT)
  val count: Long,                // Edge count
  val context: Map<String, Any?>, // Context information
)
```

### EdgeFrame 응답 {#edgeframe-response}

get 및 scan 쿼리 응답입니다. 엣지 데이터를 포함하는 페이로드입니다.

```kotlin
data class EdgeFrame(
  val edges: List<Edge>,          // Edge list
  val count: Int,                 // Number of edges currently returned
  val total: Long,                // Total edge count (-1 means not calculated)
  val offset: String?,            // Pagination offset
  val hasNext: Boolean,           // Whether next page exists
  val context: Map<String, Any?>, // Context information
)
```

### 엣지 {#edge}

개별 엣지 정보 페이로드입니다.

```kotlin
data class Edge(
  val version: Long,                 // Edge version
  val source: Any,                   // Source node ID
  val target: Any,                   // Target node ID
  val properties: Map<String, Any?>, // Edge properties
  val context: Map<String, Any?>,    // Context information
)
```
