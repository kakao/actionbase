이 가이드는 로컬 개발 및 테스트를 위해 액션베이스를 설정하는 데 도움이 됩니다. 현재 단계에서 액션베이스는 시작하고 액션베이스가 제공하는 기능을 탐색하는 데 도움이 되는 로컬 프로비저닝 옵션을 제공합니다.

## 개요

액션베이스는 두 가지 방법으로 로컬에서 실행할 수 있습니다:

1. **Gradle 사용**: `./gradlew`로 액션베이스를 직접 실행하며, 인메모리 스토리지 또는 로컬 HBase 인스턴스에 연결
2. **Docker Compose 사용**: Docker Compose를 사용하여 다양한 스토리지 백엔드(Memory 또는 로컬 HBase)로 액션베이스 실행

두 방법 모두 로컬 개발, 테스트 및 액션베이스 기능 탐색에 적합합니다.

## 사전 요구사항

시작하기 전에 다음이 있는지 확인하세요:

- **Java 17** 이상
- **Gradle 7.0+** (또는 포함된 Gradle wrapper 사용)
- **Docker** 및 **Docker Compose** (Docker 기반 설정의 경우)

## 방법 1: Gradle 사용

액션베이스를 로컬에서 실행하는 가장 간단한 방법은 Gradle을 사용하는 것입니다. 이 방법은 Docker가 필요하지 않으며 빠른 테스트 및 개발에 이상적입니다.

### 옵션 A: 인메모리 스토리지 (기본값)

액션베이스에는 추가 설정이 필요 없는 내장 인메모리 스토리지 구현이 포함되어 있습니다. 이것이 시작하는 가장 빠른 방법입니다.

**서버 실행:**

```bash
cd oss
./gradlew :server:bootRun
```

서버는 기본적으로 `http://localhost:8080`에서 시작되며 인메모리 스토리지를 사용합니다.

**참고:** 메모리에 저장된 데이터는 영구 저장되지 않습니다. 서버가 중지되면 모든 데이터가 손실됩니다. 이것은 테스트 및 개발에 적합하지만 데이터 영속성이 필요한 시나리오에는 적합하지 않습니다.

### 옵션 B: 로컬 HBase

Gradle과 함께 로컬 HBase 인스턴스를 사용하려면 먼저 HBase가 로컬에서 실행 중이어야 합니다.

**1. 로컬에서 HBase 시작**

Docker Compose를 사용하여 HBase를 실행할 수 있습니다(아래 방법 2 참조) 또는 로컬에 HBase를 설치할 수 있습니다.

**2. 로컬 프로파일로 액션베이스 실행**

HBase가 실행 중이면 `local` 프로파일로 액션베이스를 시작하세요:

```bash
cd oss
./gradlew :server:bootRun --args='--spring.profiles.active=local'
```

이것은 `localhost:2181`(기본 ZooKeeper 포트)에서 실행 중인 HBase에 연결합니다.

## 방법 2: Docker Compose 사용

Docker Compose는 로컬에서 HBase를 실행하는 편리한 방법을 제공하며, 이를 액션베이스와 함께 사용할 수 있습니다. 이 방법은 영속 스토리지로 테스트하려는 경우에 유용합니다.

### 옵션 A: 로컬 HBase

Docker Compose를 사용하여 로컬에서 HBase 실행:

```bash
cd oss/dev/hbase
docker compose up
```

이것은 액션베이스와 함께 사용할 수 있는 로컬 HBase 인스턴스를 시작합니다. HBase 인스턴스는 `localhost:2181`(ZooKeeper 포트)에서 사용할 수 있습니다.

HBase가 실행 중이면 로컬 프로파일로 Gradle을 사용하여 액션베이스를 시작하세요:

```bash
cd oss
./gradlew :server:bootRun --args='--spring.profiles.active=local'
```

데이터는 HBase 컨테이너의 볼륨에 영구 저장되므로, 볼륨이 제거되지 않는 한 컨테이너 재시작 후에도 데이터가 유지됩니다.

**참고:** Docker Compose 설정은 HBase만 시작합니다. 위와 같이 Gradle을 사용하여 액션베이스를 별도로 실행해야 합니다.

## 설정 확인

서버가 실행 중이면 액션베이스가 작동하는지 확인하세요:

**1. 서버 상태 확인**

서버는 `http://localhost:8080`에서 사용할 수 있어야 합니다. 실행 중인지 확인할 수 있습니다:

```bash
curl http://localhost:8080/health
```

**2. CLI 사용**

액션베이스 CLI가 설치되어 있으면 로컬 서버에 연결하세요:

```bash
actionbase --host http://localhost:8080 --authKey your-auth-key
```

**3. REST API 사용**

`curl` 또는 모든 HTTP 클라이언트를 사용하여 테스트할 수도 있습니다. 자세한 엔드포인트 문서는 [API 레퍼런스](/ko/api-references/query/)를 참조하세요.

## 구성

### Gradle 기반 설정

Gradle 기반 실행의 경우, 구성은 일반적으로 Spring 프로파일을 통해 처리됩니다:

- **기본값 (인메모리)**: 프로파일이 필요 없으며 인메모리 스토리지 사용
- **로컬 HBase**: 로컬 HBase에 연결하려면 `--spring.profiles.active=local` 사용

### Docker Compose 설정

Docker Compose 구성은 `dev` 디렉토리의 `docker-compose.yml` 파일에 정의되어 있습니다. 필요에 따라 포트, 환경 변수 또는 기타 설정을 조정하기 위해 이러한 파일을 수정할 수 있습니다.

## 개발 팁

### 핫 리로드

더 빠른 개발 주기를 위해 Gradle의 연속 빌드 기능을 사용할 수 있습니다:

```bash
./gradlew :server:bootRun --continuous
```

이것은 코드 변경이 감지되면 자동으로 서버를 다시 빌드하고 재시작합니다.

### 디버깅

Gradle로 실행할 때 디버거를 연결하려면 다음을 사용하세요:

```bash
./gradlew :server:bootRun --args='--spring.profiles.active=local -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005'
```

그런 다음 디버거를 포트 5005에 연결하세요.

### 로깅

애플리케이션 구성을 수정하거나 환경 변수를 사용하여 로그 수준을 조정할 수 있습니다. 로컬 개발의 경우 로깅 상세도를 높일 수 있습니다:

```yaml
logging:
  level:
    com.kakao.actionbase: DEBUG
```

## Kubernetes 프로비저닝

Kubernetes 기반 프로비저닝 가이드 및 모범 사례는 향후 릴리스에서 제공될 예정입니다. 카카오에서는 현재 Kubernetes를 사용하여 액션베이스를 프로비저닝하고 있으며, 이 Kubernetes 기반 접근 방식은 프로덕션 배포를 위해 제공될 예정입니다.

현재 로컬 프로비저닝 옵션은 액션베이스를 탐색하고 기능을 이해하는 데 도움이 되도록 설계되었습니다. Kubernetes 프로비저닝이 제공되면 다음을 포함할 예정입니다:
- Kubernetes 배포 매니페스트
- 고가용성 구성
- 성능 튜닝 가이드라인
- 모니터링 및 관찰 가능성 설정
- 보안 모범 사례
