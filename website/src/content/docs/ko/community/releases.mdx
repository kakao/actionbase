Actionbase는 변경 사항을 명확하게 전달하기 위해 [시맨틱 버전 관리(SemVer)](https://semver.org/)를 따릅니다.

## 버전 체계 {#version-scheme}

버전은 `MAJOR.MINOR.PATCH` 형식을 따릅니다:

- **MAJOR**: 호환되지 않는 API 변경 사항
- **MINOR**: 새로운 기능 추가, 하위 호환성 유지
- **PATCH**: 버그 수정, 하위 호환성 유지

Example: `1.2.3` → Major 1, Minor 2, Patch 3

## 현재 단계 (0.x.x) {#current-stage-0xx}

Actionbase는 현재 카카오 내부에서 프로덕션 환경에 운영 중입니다. 오픈 소스 릴리스는 준비 중이며, `0.x.x` 단계에서는 다음과 같습니다:

- API는 릴리스 간에 변경될 수 있습니다.
- 설치 및 운영 가이드가 준비 중입니다.
- 피드백과 실험이 환영합니다.

`1.0.0` 릴리스는 외부 사용자가 프로덕션 환경에 Actionbase를 배포할 수 있는 시점을 의미합니다.

## 호환성 보장 {#compatibility-promise}

다음은 `1.0.0` 이후 적용됩니다:

- **PATCH** 릴리스는 항상 안전하게 업그레이드할 수 있습니다.
- **MINOR** 릴리스는 기존 기능을 깨뜨리지 않고 기능을 추가합니다.
- **MAJOR** 릴리스에는 호환성 깨짐 변경이 포함될 수 있으며, 마이그레이션 가이드가 제공됩니다.

## 릴리스 후보 {#release-candidates}

릴리스 전에, 커뮤니티 테스트 및 피드백을 위해 하나 이상의 릴리스 후보(`-rc.N`)가 공개될 수 있습니다.

참여 방법은 다음과 같습니다:

- RC 버전을 프로덕션 환경이 아닌 곳에서 테스트하세요.
- 이슈는 [GitHub Issues](https://github.com/kakao/actionbase/issues)에 보고해 주세요.
- 피드백은 [GitHub Discussions](https://github.com/kakao/actionbase/discussions)에서 공유해 주세요.

## 지원 정책 {#support-policy}

현재로는 **최신 릴리스**만 버그 수정 및 보안 패치가 적극적으로 지원됩니다.

프로젝트가 성숙함에 따라, 더 긴 유지 관리 기간을 제공하는 장기 지원(LTS) 릴리스를 도입할 수 있습니다.

## 릴리스 아티팩트 {#release-artifacts}

모든 모듈은 동일한 버전을 공유하며, 함께 릴리스됩니다.

| 모듈       | 아티팩트        | 배포 방식                                  |
| ---------- | --------------- | ------------------------------------------ |
| **core**   | Java 라이브러리 | GitHub Packages (Maven Central 이후 1.0.0) |
| **server** | Docker 이미지   | `ghcr.io/kakao/actionbase`                 |
| **cli**    | 바이너리        | GitHub Releases                            |

릴리스 발표는 [GitHub Releases](https://github.com/kakao/actionbase/releases)에 게시됩니다.
